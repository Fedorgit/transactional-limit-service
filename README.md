# Transactional Limit Service

Микросервис на Java и Spring Boot для обработки банковских расходных транзакций, контроля месячных лимитов по категориям и хранения валютных курсов.

## Возможности

- Приём и сохранение расходных транзакций.
- Расчёт суммы операции в USD и проверка лимита для категории `product` или `service`.
- Создание новых лимитов в USD и просмотр истории лимитов счёта.
- Получение списка транзакций, превысивших применимый лимит, вместе с данными этого лимита.
- Хранение бизнес-данных в PostgreSQL; управление схемой через Flyway.
- Получение валютных данных от Alpha Vantage.
- REST API с Bean Validation, единым форматом ошибок `ProblemDetail` и документацией OpenAPI.
- Структурированные JSON-логи, Spring Boot Actuator и виртуальные потоки.
- Unit- и интеграционные тесты, в том числе тесты с PostgreSQL Testcontainers и WireMock.

## Настройка окружения

Приложение читает настройки из переменных окружения. Создайте в корне проекта файл `.env` со значениями, например:

```dotenv
DB_USERNAME=transactional_limit_db
DB_PASSWORD=replace_with_a_strong_password
DB_URL=jdbc:postgresql://localhost:5432/transactional_limit_db

POSTGRES_DB=transactional_limit_db

API_KEY_ALPHAVANTAGE=your_alpha_vantage_api_key
API_URI_ALPHAVANTAGE=https://www.alphavantage.co/query

POSTGRES_HOST_PORT=5432
APP_HOST_PORT=8080
```

`DB_URL` — JDBC URL, который использует приложение. При запуске через Compose для контейнера приложения URL автоматически задаётся как `jdbc:postgresql://postgres:5432/...`; имя `postgres` — имя сервиса внутри Compose-сети.

Убедитесь, что `.env` и реальные API-ключи не попадают в коммиты. В обычном локальном запуске база данных должна быть заранее создана, а пользователь должен иметь права на неё.

## Запуск

### Через Docker Compose

После настройки `.env` в корне проекта выполните:

```bash
docker compose up --build
```

Compose поднимет PostgreSQL и приложение

Данные PostgreSQL сохраняются в именованном volume `postgres_data`.

### Локально

1. Запустите PostgreSQL и создайте базу данных.
2. Установите перечисленные выше переменные окружения.
3. Выполните миграции и запустите приложение командой:

```bash
./mvnw spring-boot:run
```

В Windows используйте `mvnw.cmd` вместо `./mvnw`.

В основной конфигурации `spring.jpa.hibernate.ddl-auto` установлен в `none`: структуру БД создают миграции Flyway из `src/main/resources/db/migration/`.

## REST API

Базовый URL локального сервиса: `http://localhost:8080`.

| Метод | Endpoint | Назначение |
|---|---|---|
| `POST` | `/api/v1/transactions` | Принять и обработать транзакцию |
| `GET` | `/api/v1/transactions/exceeded?account_from=0000000123` | Получить транзакции, превысившие лимит |
| `POST` | `/api/v1/limits` | Установить новый лимит |
| `GET` | `/api/v1/limits?account_from=0000000123` | Получить лимиты счёта |

Списки возвращаются постранично. Можно передавать стандартные параметры Spring Data Pageable, например `page`, `size` и `sort`.

### Пример: отправка транзакции

```bash
curl -X POST http://localhost:8080/api/v1/transactions \
  -H "Content-Type: application/json" \
  -d '{
    "account_from": "0000000123",
    "account_to": "9999999999",
    "currency_shortname": "KZT",
    "sum": 10000.45,
    "expense_category": "product",
    "datetime": "2026-01-30T00:00:00+06:00"
  }'
```

Входные данные содержат номера счетов, ISO-код валюты, положительную сумму, категорию (`product` или `service`) и дату/время операции. Полный перечень ограничений задаётся DTO и Bean Validation в приложении.

### Пример: установить лимит

```bash
curl -X POST http://localhost:8080/api/v1/limits \
  -H "Content-Type: application/json" \
  -d '{
    "account_from": "0000000123",
    "expense_category": "product",
    "amount": 1000.00
  }'
```

Фактические обязательные поля и формат запроса определяются `SetNewLimitRequestDto`; документация Swagger показывает актуальную схему. Лимиты хранятся в USD.

### Пример: получить превышения

```bash
curl "http://localhost:8080/api/v1/transactions/exceeded?account_from=0000000123&page=0&size=20"
```

Ответ включает страницу транзакций с превышением и сведения о применённом лимите, в том числе сумму, дату установки и валюту лимита.

### OpenAPI и Actuator

После запуска:
- Swagger UI: `http://localhost:8080/swagger-ui/index.html`
- OpenAPI JSON: `http://localhost:8080/v3/api-docs`
- Actuator health: `http://localhost:8080/actuator/health`

Ошибки API возвращаются в формате `ProblemDetail`.

## Курсы валют и обработка ошибок внешнего API

Интеграция с Alpha Vantage реализована через `ExternalApiClient` и `AlphavantageService`. Список целевых валют задаётся в `src/main/resources/exchange-rates.yaml`; сейчас указаны KZT, RUB и EUR относительно USD. Обновление курсов запускается планировщиком ежедневно по cron-выражению `0 13 1 * * ?`. Запросы для нескольких валют выполняются параллельно с использованием виртуальных потоков. Для исключений `RestClientException` настроены до пяти попыток с экспоненциальной задержкой, начиная с 5 секунд.

При обработке транзакции приложение ищет сохранённый курс на дату операции или более раннюю дату. Если курс не найден, операция завершается ошибкой вместо сохранения некорректного пересчёта.

## Правила лимитов и время

- Лимиты устанавливаются отдельно для категорий расходов.
- При обработке транзакции выбирается последний лимит, установленный не позднее времени операции; если подходящего лимита нет, применяется создаваемый приложением лимит по умолчанию.
- Время транзакции нормализуется к UTC (`ZoneOffset.UTC`) перед поиском лимита.
- Данные времени хранятся в PostgreSQL как `TIMESTAMPTZ`.
- Для расчёта месяца используется UTC как единый часовой пояс, чтобы транзакции с разными исходными смещениями сравнивались согласованно.

## База данных и миграции

SQL-миграции находятся в `src/main/resources/db/migration/` и выполняются Flyway. Основные таблицы:
- `transaction` — транзакции и флаг `limit_exceeded`;
- `expense_limit` — история лимитов;
- `exchange_rate` — валютные курсы;
- `currency` — справочник валют;
- `expense_category` — категории расходов.

## Тесты

Запустить тесты:

```bash
./mvnw test
```

Запустить полную проверку сборки:

```bash
./mvnw verify
```

В Windows используйте `mvnw.cmd`. Интеграционный тест `TransactionalLimitApiIntegrationTest` поднимает приложение на случайном HTTP-порту и использует PostgreSQL Testcontainers; тесты могут пропускаться, если Docker недоступен. В тестовом профиле для части тестов используется H2 в режиме совместимости с PostgreSQL, а Flyway отключён, поэтому такие тесты сами по себе не проверяют SQL-миграции.

## Архитектура проекта

Проект создавался по луковой архитектуре, такой подход позволил разделить бизнес-правила и техническую часть проекты, при этом не перенасытить небольшой проект большим количеством абстракций.
Код расположен в пакете `com.bank.limits` и разделён по слоям:

- `domain` — доменные модели, исключения и бизнес-правила;
- `application/service` — сценарии обработки транзакций и управления лимитами;
- `application/mapper` — преобразование моделей и DTO;
- `infrastructure/persistence` — JPA-сущности, репозитории и SQL-проекции;
- `infrastructure/rest` — REST-контроллеры, DTO, валидация и интеграция с внешним API;
- `infrastructure/logging` — аспекты и конфигурация логирования.
